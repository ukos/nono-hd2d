# 大迷宮（ローグライク自動生成）キックオフ指示書 ― Claudeアプリ側エージェント向け（2026-11-18）

HD-2D lite（ブラウザ試作）の「試したいこと」の1つ、大迷宮の自動生成を、
PC側の Claude アプリで先行試作してもらうための指示書です。
lite 本体への組み込みは nono（Muse側）が後でやります。ここでは部品と実験場を作ってください。

## 作るもの（2ファイル）

1. `labyrinth.js` — 迷宮生成＋Three.js メッシュ構築のモジュール（単体で完結）
2. `labyrinth-test.html` — 動作確認用の実験ページ（Three.js 0.160.0、CDN の importmap は lite と同じものを使う）

## インターフェース（ここは固定。組み込み側がこれに合わせます）

```js
// seed から決定的に生成する
generateLabyrinth(seed, opts = {}) => {
  w, h,            // タイル数（既定 24 x 24）
  tiles,           // Uint8Array(w*h)。0=床、1=壁
  start: {x, y},   // 入口（タイル座標）
  goal:  {x, y},   // 最奥（タイル座標）。start から最も遠い到達可能タイル
  rooms: [{x, y, w, h}],  // 部屋の列（生成方式が部屋制でない場合は空で可）
}

// 生成結果を Three.js のグループにする。1タイル = 2.5m、壁の高さ 2.6m
buildLabyrinth(data) => {
  group,                 // THREE.Group（原点が迷宮の北西角の床レベル）
  colliders,             // [{x, z, r}] ワールド座標の円判定（壁タイルのうち床に接するものだけでよい）
  spawn: {x, z, row},    // start のワールド座標と初期の向き（row は lite の8方向行番号。南向き=0）
  exit:  {x, z},         // goal のワールド座標
}
```

- ワールド座標への変換： タイル (x, y) の中心 = ((x + 0.5) * 2.5, (y + 0.5) * 2.5)。lite は x が東、z が南（y を z に対応させる）
- colliders の r は 1.25（タイル半分）を基本に、角で引っかからないよう壁の並びをならしてよい（工夫は任意）

## 生成の要件

- 同じ seed では必ず同じ迷宮になる（乱数は seed 由来の決定的なもの。mulberry32 等）
- 全ての床タイルが start から到達可能（連結保証）。検証を生成時に行い、孤立した床は壁に戻すか通路でつなぐ
- 「部屋＋通路」型で、完全な一本道迷路にしない。ループ（回り道）が適度にできること
- start と goal は十分に離す（最短路長で迷宮の一辺以上が目安）
- 部屋には 2〜3 タイルの広がりを持たせ、HD-2D のカメラ（斜め見下ろし）でキャラが見える寸法にする

## 見た目（実験ページの範囲）

- 床： Canvas 生成の石畳風テクスチャ（lite の groundTexture と同じ手法でよい）
- 壁： BoxGeometry。タイルごとに高さ・色がわずかに違う（seed で決定）。フラットシェーディング
- 光： 暗い環境光＋壁の松明風の光点（glow スプライトの流用可。外部素材は使わない）
- 霧を濃くして先が見えないように（fog near 4 / far 16 程度）

## 実験ページで確認できること

- WASD・矢印キーでキャラ（簡易な板ポリゴンでよい）を歩かせ、壁にめり込まないこと
- 「次の seed」ボタンで再生成でき、毎回歩いて goal まで到達できること
- 画面隅にミニマップ（Canvas 2D で tiles を描く）を表示し、連結と start/goal の位置が目で分かること
