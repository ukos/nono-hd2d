# NONO: Blade of the Dawn ― HD-2D版 1シーン試作 検証リスト

目的：本編を移植するかどうかではなく、**「Unity → WebGL → GitHub Pages で HD-2D として成立するか」を最小コストで判定する**ための試作チェックリスト。
試作の範囲は「タイトル＋フィールド1画面分、nono が歩ける＋ライバル1体配置」まで。それ以上作り込まない。

## 0. 前提・環境

- [ ] Unity は LTS 版＋URP（Universal Render Pipeline）で新規プロジェクトを作る
- [ ] 公開先は本編と混ぜない隔離パス（例：`nono-playground/hd2d-test/`）。本編のセーブ・表示に影響しないこと
- [x] 試作シーンの題材は **水辺**（2026-11-17 決定）。既存背景（256×144）を3Dジオラマ化する題材にする
  - 水辺が試作向きな理由：水面の反射・ゆらぎは HD-2D の看板演出で、ブルームと被写界深度の効きが一番分かりやすく判定できる。夕景寄りの光と組み合わせると影・反射・にじみを1シーンで全部確認できる

## 1. 見た目（HD-2D らしさが出るか）

- [ ] 既存ドット絵スプライトをそのまま配置し、3Dの地面・建物と並べて違和感がない
  - スプライト取り込み設定：Filter Mode = Point (no filter)、Compression = None
- [ ] 斜め方向の光＋キャラクターの影が落ちる
- [ ] 被写界深度（チルトシフト風の手前・奥ぼかし）が効く
- [ ] ブルーム（光のにじみ）が効く
- [ ] 奥行きの層（手前の草・木、奥の地形）がスクリーンショット1枚で「HD-2D らしい」と言える
- [ ] 水面の反射とゆらぎ（波紋）を入れる。水際の草や小石で手前の層も作る
- [ ] 粒子（ホタル、水しぶきなど）のうち1つを入れて、演出の手応えを見る

**判定**：スクショを見て「今の2D版より明らかに良くなった」と言えなければ、ここで止める（以降の項目は無意味）。

## 2. ビルドと GitHub Pages の制約

- [ ] Player Settings で **Decompression Fallback を有効化**（Pages は Content-Encoding を返さないため）
- [ ] ビルド総量が **50MB 以内**（目安）。1ファイル **100MB 未満**（GitHub の push 上限）
- [ ] iPhone Safari で実際に起動する（wasm の読み込みエラーが出ない）
- [ ] 初回ロード時間の実測：Wi-Fi と 4G の両方で「待てる」と感じる範囲か記録する
- [ ] 2回目以降のロード（キャッシュ）が十分に速い

## 3. 性能（iPhone Safari）

- [ ] フィールドを歩き回って **30fps 安定**（ポストプロセス ON の状態で）
- [ ] 5分間動かしても Safari のタブが落ちない（メモリ上限に当たらない）
- [ ] 端末の発熱が許容範囲
- [ ] 内部解像度を落とした場合の見た目の劣化が許容範囲（解像度とポストプロセスのバランス点を見つける）

## 4. 操作

- [ ] タッチ操作（バーチャルパッド等）で歩行と基本アクションができる
- [ ] キーボード操作も従来どおり効く
- [ ] 画面サイズ・縦横比が変わっても UI が崩れない

## 5. 素材流用のコスト

- [ ] 既存スプライトシート1枚を取り込み、アニメーション（歩行など）を再現するのにかかった時間を記録する
  → 本編分（衣装・ライバル・ペット等）に換算して、現実的な工数か見積もる
- [ ] 既存の背景素材のうち、3D化せずに使えるもの／作り直しになるものの切り分けができる

## 6. 判定（Go / No-Go）

以下が全部そろえば Go：

- [ ] 1（見た目）が明確に合格
- [ ] 2（ビルド・ロード）が Pages の制約内で収まる
- [ ] 3（性能）が iPhone で実用範囲
- [ ] 5（流用コスト）の換算で、本編移植 or 短編別話のどちらなら現実的か言える

Go の場合の次の一手：移植範囲の決定（本編まるごと／短編の別話／箱庭的な実験場の拡張）。
